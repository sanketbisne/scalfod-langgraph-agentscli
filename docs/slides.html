Architecture Motivation SLIDE 02 / 10

The Framework Lock-In Problem

Teams want Google Cloud deployment, Vertex AI evaluation, and A2A serving without being forced to rewrite LangChain or LangGraph agents in ADK.

Dimension Option 1: Forking the CLI Option 2: Custom Bash Wrappers Option 3: Agents CLI Extensions (v1.8+)
Framework Support Custom fork per framework Parallel script surface LangChain, LangGraph, Deep Agents, ADK
Upstream CLI Upgrades Breaks on upstream releases; manual rebase tax Wrapper flags drift from native CLI 18+ native commands upgrade automatically
Developer & Coding Agent UX Requires installing internal fork Developers & AI assistants bypass scripts Same `agents-cli` commands with `[↑ ext]` tags
Enterprise Governance (SBOM / SSO) Hardcoded in fork Unenforced if CLI is called directly Intercepts `deploy` in-place + SHA lockfile
Key Takeaway: Adapt agents-cli to your framework and security policies via agents-cli-extension.yaml without forking. Schema: agents-cli-extension/v1alpha1

app/agent.py
from langchain.agents import create_agent
from langchain_google_genai import ChatGoogleGenerativeAI
from langgraph.graph.state import CompiledStateGraph
from app.tools import (
    create_research_plan,
    search_curated_kb,
    search_arxiv_papers,
    search_wikipedia_summary,
    critique_research_draft,
)

llm = ChatGoogleGenerativeAI(
    model="gemini-2.5-flash", temperature=0
)

root_agent: CompiledStateGraph = create_agent(
    model=llm,
    tools=[
        create_research_plan,
        search_curated_kb,
        search_arxiv_papers,
        search_wikipedia_summary,
        critique_research_draft,
    ],
    system_prompt=SYSTEM_PROMPT,
)
Unified Graph Representation: In LangChain 1.0+, create_agent compiles to a LangGraph CompiledStateGraph, allowing LangChain agents, LangGraph workflows, and Deep Agents to share the exact same runtime contract.
Agent Workflow Design SLIDE 06 / 10

DeepCite Agent Architecture (Plan → Search → Critique → Report)

Tool-driven self-reflection loop that enforces multi-source retrieval and citation verification before final synthesis.

STAGE 1: PLAN
create_research_plan

Decomposes the user prompt into 3 targeted sub-questions and recommends domain search queries.

STAGE 2: SEARCH
search_curated_kb / arxiv / wiki

Retrieves grounded passages with explicit IDs ([KB-...], [ARXIV-...], [WIKI-...]) and offline fallbacks.

STAGE 3: CRITIQUE
critique_research_draft

Audits draft claims against retrieved source IDs. Requires ≥ 2 distinct citations and technical depth or triggers revision.

STAGE 4: REPORT
Cited Markdown Output

Synthesizes the final Markdown brief with inline [SOURCE_ID] tags and a verified ## References bibliography.

Deterministic Evaluation Ready: Built-in curated KB and ArXiv/Wikipedia fallbacks guarantee 100% reproducible CI evaluation runs without flaky external API timeouts.

Act 3 • Evaluation Pipeline SLIDE 08 / 10

Framework-Agnostic Evaluations (eval generate + eval grade)

Trace generation is overridden to run the LangGraph graph; grading and comparison use the native Vertex AI Evaluation Service.

STEP 1: GENERATE TRACES [↑ langchain]

Drives root_agent.invoke() across basic-dataset.json and records tool trajectories:

agents-cli eval generate \
  --dataset tests/eval/datasets/basic-dataset.json \
  -o tests/eval/output/
STEP 2: GRADE & COMPARE (Native CLI)

Scores standard EvaluationDataset traces against Vertex AI rubrics:

agents-cli eval grade \
  --traces tests/eval/output/basic-dataset.json \
  --config tests/eval/eval_config.yaml
CLEAN REFUSAL FOR ADK-ONLY SUBCOMMANDS
$ agents-cli eval dataset synthesize
agents-cli eval dataset is not supported by the langchain extension:
it runs the agent through ADK's user simulator, which needs google-adk in this project's venv.
Explicit refusals prevent coding agents and CI pipelines from retrying unsupported commands in a loop.
Act 4 • Custom Governance Extensions SLIDE 09 / 10

Authoring Custom Enterprise Extensions (sbom-deploy & research-report)

extensions/sbom-deploy/agents-cli-extension.yaml
schema: agents-cli-extension/v1alpha1
name: sbom-deploy
description: Scan project SBOM, then run native deploy.
requires:
  agents_cli: ">=1.5,<2"
  on_incompatible: warn

commands:
  override:
    deploy:
      run: ["bash", "scripts/sbom_then_deploy.sh"]
      description: SBOM scan via syft+grype, then deploy.
  add:
    sbom-report:
      run: ["bash", "scripts/sbom_report.sh"]
      description: Produce an SBOM audit (no deploy).
scripts/sbom_then_deploy.sh
#!/usr/bin/env bash
set -euo pipefail

echo "[sbom-deploy] Generating CycloneDX SBOM..."
syft dir:. -o cyclonedx-json > /tmp/sbom.cdx.json

echo "[sbom-deploy] Scanning for critical CVEs..."
grype sbom:/tmp/sbom.cdx.json --fail-on critical

# AGENTS_CLI_DISABLE_OVERRIDES=1 is set by loader
# Calls built-in deploy with zero recursion!
echo "[sbom-deploy] SBOM clean; running native deploy..."
exec agents-cli deploy "$@"
$ agents-cli extension add local@./extensions/sbom-deploy --yes $ agents-cli deploy --dry-run
